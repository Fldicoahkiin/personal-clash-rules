# 本地与云端转换、刷新保护

## 本地不是浏览器离线转换

第三方 sub-web 的「localhost:25500」只是把下载地址指向本机的 `/sub` 服务，它不会替用户安装或启动转换器。端口没有服务会连接失败；服务把不存在的 `/sub` 回退到 HTML 首页，就会出现「Profile is not a valid YAML」。本站本地服务现在为 `/sub` 返回真实 YAML，未知入口返回 404。

本地服务和 CF 导入同一个 `src/worker/subscriptions.ts`，使用相同解析、分组、DNS 模板和转换代码。远程规则提供器使用同一套公开规则地址；本地程序和内置规则文件仍需通过 Git 更新并重新构建，不会自动下载执行新代码。比较页面提交 hash 可以判断版本是否一致。更新本地服务不要求改变当前代理客户端设置。

本地从用户设备的出口读取机场，有时可读到拒绝 CF 的来源；这不是稳定性保证。本机休眠、服务停止、网络故障仍会影响刷新。`127.0.0.1` 是每台设备自己，手机不能通过它访问电脑。云端链接不依赖电脑开机，但受上游对 CF 的访问策略与 Workers/KV 配额限制。

## 区分上游拒绝和转换故障

生成接口遇到上游 HTTP 错误时返回 `source_failed`，并附带 `upstream`：上游状态码、读取时间、重定向次数、响应类型分类、Cloudflare 标记及格式有效的 Ray ID。不返回源 URL、Cookie、任意响应头或正文，也不写入这些私密内容的日志。Ray ID 和时间可交给机场运营方查询拦截记录。

只有 `cf-mitigated: challenge` 才明确标记为浏览器验证页；普通 403 不足以证明是 IP、UA、地区或某条 WAF 规则。机场可能把有效 YAML 的 Content-Type 也写成 `text/html`，因此不能仅凭 HTML 类型认定被拦截。429 单独提示限流，不自动连续重试。

CF 后端不能完成交互式浏览器验证；这不等于机场接口坏了，也不等于转换器适配已经完成。本站提供显式的本地读取与云端同步路径：本机经已有代理读取成功后，将已验证的节点、名称和用量上传到自己的 CF，手机从固定云端链接下载。修改本机 DNS、TUN 或系统代理不会改变 Worker 到机场这一段的验证。系统不复制浏览器通行 Cookie、不伪造访客地址、不暗中改用第三方转换服务。

## 本地读取，云端分发

1. 选择本地后端，或打开正在运行的本地站点。用原机场订阅和独立节点正常生成，先检查节点数和用量。
2. 点击「同步到我的 CF」。上传包括原始节点账号密码、源订阅地址、规则选择及响应头里的名称/用量；固定发送给 `https://rules.flacier.com`，不是公共转换服务。云端链接本身能读取凭据，不要公开。
3. 本地服务每分钟检查任务，按该订阅的更新间隔同步。手机读取云端链接时不再要求 CF 直接访问机场。单来源缓存 5 分钟，按 URL 和 UA 隔离；缓存前必须解析出节点，正文与名称/用量一起缓存。
4. 每次更新先在本地验证，再由 CF 验证全部来源与目标输出，成功后替换同一条 KV 记录。管理密钥只保存在本地，CF 只保存其散列；读取链接不能用于上传覆盖。上传失败保留原链接和旧内容，15 分钟后重试。
5. 「查看 / 刷新同步任务」可以查看最近同步时间、暂停和恢复。暂停不会撤销云端链接。编辑输入后重新生成属于新任务；旧任务应手动暂停。本地服务不安装开机启动项，关闭服务或电脑休眠就不再同步。

响应头包含 `X-Subscription-Source-Mode: local-sync`、`X-Subscription-Synced-At`。超过设定更新间隔 10 分钟以上仍保留上次内容，但设置 `X-Subscription-Refresh-Status: sync-overdue` 和 Warning；用量也是同步时的数据。网页结果显示同步时间，不宣称实时读取。对于离线很久的任务，需要重新验证凭据和节点，不能仅凭能下载云端 YAML 就判定可连接。

限制：最多 10 个机场源，单源 1 MiB、原始正文合计 1.8 MB、同步 JSON 请求和存储记录各 2 MiB。额外的 SOCKS5/HTTP 节点仍保存在配置中。同步是一个本地任务单写者模型，最短 60 秒一次；KV 跨地区最终一致，不能承诺多台电脑同时编辑时的强一致顺序。没有自动同步到其他 CF 账户/域名，也没有把任意 VPS 程序搬到 Worker。

若还要串联 Rola，可以在云端「机场 → Rola」中使用已同步的基础订阅，选择具体前置节点再生成。此时 CF 读取的是本站的同步结果。同步来源仍受本机在线时间限制，Rola 握手和实际出口必须另测；普通合并两种节点不等于串联。

## 刷新不是永久追加

- 所有来源成功并产生节点后，才发布新的完整结果。成功结果会移除机场明确撤回的旧节点，防止陈旧凭据永久积累。
- 任一来源错误、超时或返回零节点时，不发布只剩其他来源的残缺结果。独立 IP 保存在生成配置中，不会因为机场失败而被清空。
- `/s/`、云端 `/r/` 与兼容 `/sub` 保存最近完整结果。最多回用 24 小时，按目标格式隔离；KV 快照写入间隔至少 60 秒，所以恢复结果可能比最近一次成功响应早一分钟。缓存写入失败仍可返回当次有效内容，但明确设置 `X-Subscription-Recovery-Storage: unavailable`，不能保证后续恢复。
- 恢复响应含 `X-Subscription-Refresh-Status: last-good`、`X-Subscription-Last-Success`、脱敏错误代码及 Warning。其中流量、有效期也是该时间的数据，不是实时查询。无有效快照时返回非 2xx，不生成 COMPATIBLE 外壳。
- 配置校验失败、前置节点被删除或变为不安全，不会用恢复机制掩盖。返回错误，让客户端保留已下载配置，用户需重新选择节点并验证。

转换器无法控制客户端是否在错误后保留文件，也无法撤回已下载副本。KV 最终一致性与网络分区不是事务数据库保证。

## 名称和用量

单机场可继承 Content-Disposition / Profile-Title 的名称，手动输出名称优先。多机场在有名称元数据时为节点加机场前缀；独立代理用 URI 备注，网页提供字段输入与四段格式拆分。显示已用、总量、剩余、有效期；没有上游响应头就显示未知。多机场全部提供用量时合成 Subscription-Userinfo，正数到期取最早值；独立套餐不能互相转移余额。串联家宽不能和机场额度相加。

## /sub 兼容范围

支持 `target=clash/clashr/mihomo`、`url`（竖线分隔）、`config`（受支持的 ACL4SSR INI）、`filename`、`ua`、`list`、`include`、`exclude`、`sort`、`emoji`、`append_type`、`udp`、`tfo`、`scv`、`fdn`、`expand`、`new_name=true`、`insert=false`。布尔大小写均可。默认完整 Mihomo 配置，`list=true` 输出仅节点。`fdn=false` 遇到目标不支持的节点会拒绝，不编造协议转换；`scv=true` 会降低证书验证安全性，不建议默认开启。

展开最多 32 个 classical text 规则源，原始规则合计最多 1 MB，输出最多 1.8 MB；太大时选择 `expand=false` 由客户端按规则提供器读取。未知参数、脚本、旧字段名、未实现的 INI 指令明确返回错误；不是整个 subconverter 二进制的等价实现。其他目标客户端使用本站网页。兼容 URL 查询参数可能含凭据，优先使用本站 POST 生成不透明短链接。
