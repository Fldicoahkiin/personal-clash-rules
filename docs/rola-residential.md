# Rola 住宅出口：云端与本地准备、验收

支持两种账号格式：控制台提供的现成 HTTP/SOCKS5 节点选择「用户名原样使用」；Rola 动态住宅基础账号选择「拼接国家与会话」。现成节点不追加任何后缀，也不根据 IP 外观推断它是否固定或独享。动态住宅的官方会话参数只承诺尽量保持，时间范围 1–120 分钟；重新连接、资源失效或会话到期仍可能换 IP。这里不代购、不重置密钥、不修改白名单，也不调用刷新 IP 或购买接口。

## 两条路径不要混淆

```text
配置：机场完整配置 + Rola 设置 → 云端或本地生成候选 YAML → 检查/导入客户端
流量（直接接入）：设备 → Rola 住宅出口 → 选定网站
流量（机场前置）：设备 → 指定的机场节点 → Rola 住宅出口 → 选定网站
```

Cloudflare 和本地转换器只生成配置，不承担第二条路径的转发。无需自建 VPS。网页「机场 → Rola 家宽出口」默认将 Rola 密码交给本站 CF；如不愿上传，可切换「本地服务 · 私密覆写」。普通模式把两种节点合并仍不等于代理链。

### 直接接入与机场前置

网页「Rola 家宽出口」现在可明确选择两种接入方式。默认仍是机场前置；旧记录省略 `connectionMode` 时也保持串联。

- `chain`：设备 → 指定加密机场 → 家宽 → 网站。需要一个实际机场节点，失效不自动换前置或降级直连。
- `direct`：设备 → 家宽 → 网站，不经过机场。必须主动选择，不能同时提交前置节点；生成节点使用 `dialer-proxy: DIRECT`。这表示直接连接代理网关，不是直接访问目标网站。普通 SOCKS5/HTTP 的认证与目标地址没有代理协议自身的加密，网站 HTTPS 是另一层保护。

直接接入还会在 Mihomo 规则最前面加入「精确网关主机 + 端口 → DIRECT」。`dialer-proxy` 只控制 Mihomo 自己建立的节点连接；外部代理客户端通过本机代理端口或 TUN 访问同一住宅网关时，也需要这条例外，避免被兜底策略再次送入机场。它不放行整个进程、其他端口或目标网站；机场前置模式不生成这条例外，Shadowrocket 配套配置也不携带这条桌面规则。

两种方式都支持自定义家宽分组名称；组中只包含明确加入的家宽节点，不把机场或 DIRECT 当作故障备用。机场前置模式仍限一个家宽出口，直接接入模式可加入多个独立出口。旧记录的默认组名仍为 `ROLA`。家宽与机场分别计费，响应头只继承已取得的机场用量，不能将静态家宽的有效期伪装成机场到期时间。

Flacier 的 Mihomo 模板将「🖐 手动选择」放在第一位、「🌐 全局」放在第二位；加入家宽后，第三位是专用家宽组，其后是「♻️ 自动选择」和国家／业务组。手动组可选实际机场节点、国家组、自动组；手动、全局和所有业务组都可选专用家宽组。使用名称中的旗帜和 emoji，不依赖远程 SVG。Mihomo 自带的 `GLOBAL` 模式组不等同于这里的「🌐 全局」，国内白名单需要客户端处于规则模式。

国家组按地区收录节点，不区分机场或家宽来源。家宽优先按 `settings.country` 加入对应国家组；未声明时才沿用已有的节点名称地区过滤规则，无法识别则不猜测。节点备注不含国家名也不影响明确声明的地区；已有国家组没有覆盖该地区时，只保留独立家宽组和业务组中的选择。国家组直接收录实际家宽节点，不引用家宽组形成组循环。「♻️ 自动选择」仍排除家宽，其他国家组也不会误收录。`DNS-PROXY` 排除“剩余流量／到期”等展示节点，不能把机场的额度提示当作 DNS 出口。更改组名后客户端旧的已选出口或显示顺序可能失效，需要核对实际运行配置；生成器不会替用户切换客户端。

`DNS-PROXY` 允许手动选家宽，但不会因新增家宽而改掉原来的默认机场，也不把家宽加入自动测速。能够从基础配置确认原默认节点时，生成器保留组的动态过滤与来源，设置 `default-selected` 后开放家宽选项；若外部 provider 或自定义过滤使原默认无法确认，则维持原组行为，并在生成结果中提示“尚未加入家宽”。这不会改动已运行客户端的选择缓存；业务域名另有 AI／家宽 DNS 策略时，仍优先遵从该策略。

### 多个独立家宽与节点备注

同一订阅最多包含 **8 个家宽出口：首个出口加 7 个附加出口**。这只适用于「直接接入家宽」，不是「家宽 A → 家宽 B」的串联，也不是自动轮换。专用家宽组保持手动选择，用户每次选择其中一个出口；各出口按自己的国家标签加入对应国家组。所有家宽都排除在 `AUTO`／「♻️ 自动选择」之外，失败不会自动改走机场或 DIRECT。新增家宽不改变 `DNS-PROXY` 原有默认出口；业务域名的显式 DNS 策略仍按上一节处理。

- 云端：填写首出口后，点击「添加独立家宽出口」。附加出口使用现成 HTTP／SOCKS5 节点及原样账号；每一项填写自己的接入网关、端口、账号密码和备注。生成时连同首出口上传本站 CF，不写入浏览器本地存储。
- 本地：先使用原来的添加／保存出口功能保存各条节点，再选首个出口并勾选「附加家宽出口」。只提交本机保存的出口 ID，凭据仍由本机服务读取；首个出口不能再重复勾选。附加项仅支持原样账号，动态住宅账号仍可作为单独的首出口使用。
- 切回「机场前置 → 家宽」时，界面保留附加内容或勾选，但阻止生成并说明原因。需要切回直接接入，或明确移除附加项，不会静默丢弃节点。

**接入网关与出口 IP 是两个不同字段。** 网关及端口决定设备连接哪里；出口 IP 是网站实际看到的地址，可与网关不同。「出口 IP」和「出口区域」一起填写后，节点名称显示为 `203.0.113.10 · 美国 Test Region` 这样的备注；这个示例地址仅供说明。若两者都不填写，则使用备用备注。填写备注不会改写连接网关，不会自动检测或证明 IP／城市，也不代表出口固定或独享；国家归组仍由国家代码控制，不从城市文本猜测。

同一记录中的节点名称及接入凭据组合不能重复。新增出口、修改 IP／区域、凭据或规则后，都需要重新生成订阅并使用新链接；已有云端记录、本地链接及已下载配置不会自动增加或改名。手机首页节点订阅与配套配置需保持同一批节点名称，但输出校验不等于 iOS 实机导入、出口或 DNS 已验证。

## 国内应用直连白名单

Flacier 模板保留 QQ／微信（含图片、头像、表情、小程序、腾讯会议）和网易云音乐的独立 `DIRECT` 规则集；增加国内服务域名集合，覆盖抖音视频／图片／API、快手、小红书、淘宝／支付宝／京东、高德、美团、12306 等。Bilibili 策略组默认直连，仍可手动选其他出口。域名来自 [MetaCubeX 编译后的 geolocation-cn](https://github.com/MetaCubeX/meta-rules-dat/blob/meta/geo/geosite/classical/geolocation-cn.list)，补充 [v2fly 小红书](https://github.com/v2fly/domain-list-community/blob/master/data/xiaohongshu)、高德与公司列表中明确的国内应用依赖；现有腾讯／网易来源不变。不导入整个 ByteDance、ChinaMax、共享云 ASN 或关键词规则，不把 TikTok、海外 ByteDance、GitHub、OpenAI 当成国内应用。

顺序为用户显式规则、已有业务分流、国内域名直连、`GEOIP,CN,DIRECT,no-resolve`、未知流量代理。AI／开发／海外业务规则在国内兜底前，避免被中国 CDN IP 覆盖。CN IP 规则只检查已有目标 IP，不为它额外查询 DNS；无法辨认的连接仍走代理，不是 `MATCH,DIRECT`。IP 归属依赖客户端 GeoIP 数据库，不能当作服务所属国家的证明。

直连意味着这些服务能看到设备所在网络的公网出口；它不是匿名选项。此次只改分流，不开启 DNS 覆写、嗅探或 TUN；业务 DNS 仍沿用已选模式，选择代理 DoH 时国内网站的 DNS 也仍走代理。域名数据共享于 Mihomo／Shadowrocket 文本、Egern YAML 和 sing-box JSON；CN IP 兜底当前随 Mihomo、Shadowrocket、Surge、Stash 完整配置输出，其他渲染器不能据此声称已有同样的 IP 兜底。

Shadowrocket 手机端需刷新并选中配套 `.conf`，全局路由使用「配置」而不是「代理」。只刷新首页节点订阅不会安装分流规则；来源节点改名后两份资源都要刷新。桌面日志能帮助补公共服务域名，但不能证明手机抖音、微信等实际连接已验证。规则同步使用已编译的地区筛选，不自行丢弃上游 include 的属性语义；跨格式不支持的正则逐条记在文件头。响应超时、非文本、HTML、超过 1 MiB 或空数据都会使同步失败并保留旧文件，源 URL 与内容 SHA-256 留在快照中供排查。

受保护域名可显式选择 `AI` 策略（`policyGroup: "AI"`），或选择专用家宽组（`policyGroup: ""`）。AI 策略把家宽设为 AI 的默认选项，匹配域名的连接与 Mihomo DNS 跟随 AI 组的手动选择，不会在 AI 改为机场后仍被更早的固定家宽规则或 DNS 策略抢先匹配。旧记录省略该字段时，有 AI 组便跟随 AI；基础配置没有 AI 组时才使用专用家宽组。显式选择专用家宽组的设置保持固定家宽，不改变其含义。

诊断时先比较相同协议、凭据和目标在物理网卡直达与不同机场前置下的结果。一次 TCP 连接建立不代表 SOCKS5 认证成功；某条前置失败也不代表家宽账号不可用。切换测试必须建立新连接，不能复用上一个出口的 HTTP 连接。浏览器检测页面及其测试域名也需要核对实际路由。

HTTP/SOCKS5 是官方文档明确的接入方式，本工具不推断 TLS 网关或 UDP 支持。第一跳机场应提供加密；普通 HTTP/SOCKS5 在**机场到 Rola**这一段仍没有代理协议自身的加密，网关认证与目标地址可能被该段观察者看到。目标网站的 HTTPS 是另一层保护，不能把它说成整条链路都加密。不关闭证书校验；是否有可用的 TLS 网关要由 Rola 明确提供。

## 网站默认：Cloudflare 串联

1. 选择「机场 → Rola 家宽出口」，保持「Cloudflare 云端（默认）」。填入机场订阅或加密节点，点击读取，选择一个具体的前置节点。
2. 填写供应商实际协议（SOCKS5 / HTTP）、原样账号密码和自定义节点备注；只有购买动态住宅产品时才使用动态账号拼接。
3. 编辑经家宽的 DOMAIN / DOMAIN-SUFFIX 规则、DoH，点击上传生成。输出适用于 Clash Party、Verge、FlClash 与 Mihomo。Shadowrocket 不能使用该 YAML 串联。
4. 保存管理文件。随机链接是读取完整凭据的凭证，删除码与链接分开验证；管理文件也不能公开。页面不自动导入、启用 DNS 覆写或切换代理。
5. 测试后导入。CF 读取机场被拒绝时，不偷偷切换后端；可显式选择「上传完整配置快照」。快照只包含上传时的节点，不自动刷新用量，不伪造 `Subscription-Userinfo`。

数据限制：最多 3 个来源、500 个机场节点；单个机场原始响应 1 MiB，上传快照和转换后的基础配置各 256 KiB，请求 512 KiB，存储记录 1 MiB，最终串联输出 512 KiB。预览记录 1 小时，生成的云端串联记录 90 天，到期要生成新链接。采用逐个读取来源和大小限制，不能保证任意并发下都不会触及 Worker 内存/CPU 配额。CF KV 不适合作为秒级强一致管理数据库，生成、删除跨地区可能延迟。删除会同时清除该串联的恢复快照；若链接已经泄漏，还应更换供应商密码。

刷新会重新读取机场并继承其用量头；读取失败或空来源时可以回用 24 小时内的完整有效输出，响应头标记 `last-good` 和旧结果时间，用量也可能滞后。没有有效快照或超过 24 小时则返回错误。选中的前置节点消失/证书条件变差时直接拒绝更新，不自动选别的出口。详细语义见 [刷新保护](subscription-refresh.md)。

## 网站可选：本地服务与私密覆写

1. 在项目目录运行 `pnpm build && pnpm start:local`。这只是本地转换服务，不启动/切换任何代理客户端。需要现有客户端帮助读取机场时，显式加 `--proxy http://127.0.0.1:混合端口`；不修改系统代理。
2. 在网站「转换方式」选择「机场 → Rola 家宽出口」，将后端切为「本地服务 · 私密覆写」，点击「连接本地服务」。此模式只向 `http://127.0.0.1:25500` 发送 Rola 相关请求；如果浏览器阻止本地网络访问，打开 `http://127.0.0.1:25500/#subscription` 使用相同界面。服务不可用时不自动退回 CF 或自定义云后端。
3. 填机场订阅或节点，选择 Clash Party / Clash Verge / FlClash / Mihomo，点击「读取机场节点」。此模式使用 Flacier 完整配置、独立系统引导 DNS、代理 DoH 和 6 小时更新间隔，不使用客户端直读兜底。预览需要读取上游，不证明节点连通。
4. 从实际读取的节点中选择一个前置节点。未加密、已串联或跳过证书验证的节点不可选。添加并保存 Rola 出口，可在多个已保存出口之间选择；编辑时账号/密码留空保持旧值，不回显已有凭据。
5. 编辑经 Rola 的域名规则，支持 `DOMAIN` / `DOMAIN-SUFFIX` 两列格式与 `#` 注释。匹配流量优先经 Rola；其他流量仍遵循基础 Flacier 配置，不代表全设备流量都走住宅出口。DNS 区可编辑这些域名的 IP 地址 DoH。
6. 生成新的本地订阅，手动复制链接或下载候选配置。没有自动导入按钮；不会切换当前可用配置。修改来源、节点、出口、规则或 DNS 后，旧结果在页面中清除，需重新生成。
7. 需要云端基础订阅时，再点击「生成云端基础订阅（仅机场来源）」。这一步明确将机场来源交给本站 Cloudflare；不会发送 Rola 出口、账号密码或私密域名规则。得到的云端链接只有机场配置，家宽链路仍由本机私密覆写添加。云端生成失败保留本地结果，不改后端重试。

网页记录位于 `.local/rola/web/`，目录 `0700`、文件 `0600`，机场来源仍放在本机 `.local/subscriptions/`。不使用浏览器 localStorage、云端 KV、URL 查询参数存凭据，接口列表不返回账号/密码。文件是**本地明文**，不是加密保险箱；不要同步/上传这些目录或候选配置。CLI 的 `.local/rola/settings.json` 与网页记录相互独立，不自动读取或覆盖。

本地订阅每次被客户端更新时，会重新读取机场并验证选中的前置节点。机场读取失败时，基础订阅可回用 24 小时内的完整结果；无可用结果、节点消失或 DNS/规则校验失败时返回错误，不输出空配置、不改用 DIRECT。机场返回的 `Subscription-Userinfo` 继续传递，Rola 不与其合并。生成时保存出口快照，后续编辑已保存出口不会改变旧链接；换密码或分流需要生成新链接。

本机链接只有这台电脑可访问，本地服务要保持运行；不要给它开公网隧道。iPhone/另一台 Android 不能使用电脑的 `127.0.0.1`，只能私下传输候选文件或另行安排可信同步。Shadowrocket 不接受 Mihomo YAML，仍需按下文设置代理通过；网页不声称已适配其 Rola 链路。

## CLI 本地准备（可选）

```bash
pnpm rola init
```

生成 `.local/rola/settings.json`，权限 `0600`，目录 `0700`，已被 Git 忽略。再次初始化不会覆盖。用本地编辑器填写，不把密码放在命令行、截图、Git、在线页面或聊天中。

| 字段 | 填什么 |
| --- | --- |
| `authMode` | `literal` 原样使用完整账号，或 `dynamic` 拼接 Rola 动态住宅参数；旧设置省略时仍按 `dynamic` 解释 |
| `protocol` | `socks5` 或 `http`，与控制台选项一致 |
| `server` / `port` | 控制台实际网关及对应端口；不猜端口 |
| `platform` | 平台名称，缺省或空白为 `Rola`；去掉首尾空格后最多 24 字，只允许文字、数字、空格、点、下划线和连字符，不能含方括号或配置分隔符 |
| `exitIp` / `region` | 可选且成对填写，节点名称统一为 `[平台] 地区 · IP`；不替代 `server`，不自动证明 IP 或地区。旧记录两项均为空时保留原备注 |
| `account` / `password` | `literal` 填控制台提供的完整账号与密码；`dynamic` 的 `account` 只填基础账号，不含地区/会话后缀 |
| `country` | 两字母国家代码，用于地区标签和国家组归属；动态模式同时用于官方账号参数，原样账号模式可留空，留空才按现有节点名称地区规则归组 |
| `sessionId` | 固定的字母数字标识，1–32 位；默认 `main`，生成文件时不自动换会话 |
| `sessionMinutes` | 1–120，初始为 120；不是固定 IP 保证 |
| `upstreamNode` | 原完整配置 `proxies` 中一个具体机场节点的完整名称，不填 `AUTO`、国家组或 `DIRECT` |
| `rules` | 两列的 `DOMAIN,主机` 或 `DOMAIN-SUFFIX,域名`；初始复用仓库 Claude/OpenAI 域名表并附 GitHub，按使用习惯编辑 |
| `dns` | 为这些域名使用的 IP 地址 HTTPS DoH；Mihomo 跟随所选 AI 或专用家宽策略，不接受带自定义路由参数的 URL |
| `apiToken` | 可留空；只在明确执行 `usage` 时使用，和代理密码不同 |
| `additionalExits` | 直接接入时最多 7 个附加原样账号出口，与首出口独立选一；每项使用自己的协议、网关、端口、凭据与备注，不能嵌套 |

只有 `dynamic` 模式按官方格式组合为 `基础账号_会话-country-国家-sessiontime-分钟`。`literal` 模式保持账号逐字不变，国家用于可选地区标签及归组，忽略会话字段；不要把现成节点误配为动态账号。此入口不提供 `-f-1` 逐请求轮换或州/城市筛选。

例如 `platform: Rola`、`region: 美国 Las Vegas`、`exitIp: 203.0.113.24` 会显示为 `[Rola] 美国 Las Vegas · 203.0.113.24`。此处为文档示例地址，不是可用节点。网页、本地和云端输出使用同一命名方式；平台名称只用于显示，不参与账号拼接或线路选择。

导出一份**已经可以使用的完整 Mihomo 配置**，不要直接拿空的 `proxy-providers` 外壳来生成：

```bash
pnpm rola prepare --base /本地路径/原配置.yaml
```

每次生成独立的 `.local/rola/candidate-*/mihomo.yaml` 与脱敏 `summary.json`，不会覆盖原文件，不会打开客户端、切换订阅、启动 TUN 或发出代理请求。候选文件包含密码，只能保留在本地私有位置；不是可以公开托管的规则模板。原机场节点更新后要从新的完整配置重新生成，不能指望这一份本地快照自动更新节点、Rola 密码或额度。

生成器会：

- 固定第一跳节点，用 `dialer-proxy` 建立到 Rola 的连接；拒绝已存在的前置代理链、未加密的第一跳、跳过证书校验或空节点。
- 为选定域名优先加上所选 AI 或专用家宽策略。专用家宽组仅包含 Rola，没有 `DIRECT` 或其他出口备用；失效时不悄悄换出口。
- 将家宽实际节点加入匹配的国家组，保留独立家宽组；「♻️ 自动选择」及其他地区仍排除它。手动／全局／业务组可显式选择专用家宽组。客户端手动“测试全部节点”仍可能消耗住宅额度。
- 明确拒绝选定域名的 UDP，Rola 节点与组均禁用 UDP。网页可能改用 TCP；纯 UDP 的语音/游戏会不可用，不能承诺无差异。
- 仅为选定域名添加代理 DoH 策略，并关闭候选配置的 IPv6。原默认解析器、引导解析、TUN、嗅探、其他规则、注释和未知字段保留。已有 DNS 策略冲突会报错，不替你覆盖。

第一跳和 Rola 网关的引导 DNS 必须独立于 Rola，防止“连接代理需要 DNS、DNS 又需要这个代理”的循环。当前支持已有 `proxy-server-nameserver` 中的 `system`、IP 或 IP 地址 DoH。带主机名的 HTTPS 解析器仅在存在独立 IP 引导、未启用 `respect-rules` 且不与保护域名重合时保留；否则拒绝生成，不自动改原 DNS。系统引导可能仍访问本地 DNS，不能称作所有解析都离开中国。候选配置也不能阻止浏览器/操作系统绕过客户端自行解析；DNS 覆写或全局脚本可能再次替换它。

HTTP/SOCKS5 还可能把目标域名交给 Rola 服务端解析。本地 DoH 策略不能决定服务端使用哪家解析器，住宅出口的国家也不能保证 DNS 解析器属于同一国家。这部分要购买后按实际节点测试，不能仅凭配置文件承诺 BrowserLeaks 没有中国结果。

## Shadowrocket / FlClash

- Clash Party、Clash Verge 和 FlClash 使用同一 Mihomo 候选 YAML，但各客户端的全局覆写仍需检查；不替换当前可用订阅。
- 云端返回 `universalUrl`（`/r/随机令牌`）。请求 UA 为 Clash Party / Clash Verge / FlClash 时返回完整 Mihomo；Shadowrocket 返回同一来源的机场和住宅节点 URI。`url` 的 `.yaml` 后缀仍是固定 Mihomo 下载地址；不把 YAML 冒充手机适配。
- 对直接家宽，`shadowrocketConfigUrl`（同一链接加 `?target=shadowrocket-config`）返回配套 `.conf`。先把通用链接添加到 Shadowrocket 首页的订阅，再把配套链接添加到配置页并启用。手机配置不生成手动／全局／AI／家宽策略组：国内白名单直连，其余代理流量和代理 DoH 跟随首页当前节点。节点新增或改名不需要同步配置中的节点引用；分流规则或 DNS 改动后刷新配套配置。
- 手机配套文件关闭 IPv6，拒绝不支持的 UDP，业务、直连规则和备用 DNS 均使用 IP 地址 DoH 加 `#proxy`，跟随 **Shadowrocket 首页的默认节点**。家宽不可用时需在首页选择可用节点。此语义来自 [Shadowrocket 官方 2.2.62 说明](https://t.me/s/shadowrocketnews?before=890)，不将任意策略组名当作受支持的 DNS 节点名。节点主机名保留独立引导 DNS，业务 DNS 失败不会自动退回直连解析；配置文件不含密码，但配套订阅包含凭据。节点改名或新增后刷新首页订阅即可；分流与 DNS 的修改另行刷新配套配置。
- 机场前置串联不输出手机 URI，返回 `rola_mobile_chain_unsupported`；不会丢掉第一跳后假装转换成功。其他不支持的客户端、无法保留的节点／代理链／规则也明确报错。每种输出独立保存最近成功结果，避免手机刷新失败时拿到旧 YAML。
- iPhone 上的实际导入、网络出口和 DNS 仍需验收；服务端测试只证明输出和元数据一致，不代表手机已连接。

生成结果提供「下载 Clash Party 本地私密覆写」。这是带有家宽账号密码的 `main(config)` 脚本，只从本机后端下载。云端继续更新不含家宽凭据的基础订阅；脚本在 Clash Party 本机叠加住宅节点、独立代理组、目标域名规则和 DNS 策略。

按 [Clash Party 官方说明](https://clashparty.org/docs/guide/override) 从本地文件导入覆写，只绑定选定的基础订阅，不全局启用。不要给覆写创建公网链接，也不要用 WebDAV 上传它。前置节点名必须与生成时一致；机场刷新其凭据可以继续使用，若节点名消失、加密/证书条件变差、引导 DNS 或原 DNS 策略变化，会拒绝覆写，需重新生成和验收。脚本抛错后的处理由客户端决定，不能把拒绝生成等同于客户端全局断网保护。

## 独立限时回退（默认不启动）

`scripts/config-guard.mjs` 只在明确执行 `start` 时修改所指定 Mihomo 实例的**运行配置**；网站生成、保存、下载都不会启动它。先用独立 Mihomo `-t` 检查候选文件，确保原文件是该实例当前可用配置，再执行：

```bash
node scripts/config-guard.mjs start --baseline /本地/当前可用.yaml --candidate /本地/候选.yaml --socket /本地/控制接口.sock --label "只修改一项 DNS 设置" --seconds 90
node scripts/config-guard.mjs status /返回的/trial目录
# 确认浏览器、Codex 会话和原有业务均正常后，才保留此次运行配置：
node scripts/config-guard.mjs confirm /返回的/trial目录
```

独立子进程不依赖 Codex 继续发命令；未确认超时、连续两次健康检查失败、应用请求异常时恢复快照。恢复请求本身也有限时；接口不可用或恢复后仍不通时明确记为 `rollback_failed` / `rollback_unhealthy`，不是成功。已保存的客户端订阅、GUI 开关与 OS 系统代理不在此工具的修改或恢复范围内。不要在试运行期间手动切换订阅/开关、重启客户端或启动第二次试运行。电脑休眠、进程被强制杀死、控制接口退出等场景不能保证按时恢复。

默认只允许一个配置字段发生变化；整份候选需要额外 `--allow-batch`，此时只能定位到这次组合变更，不能声称是某一个选项导致。试运行禁止更改用于探测的 mixed 端口、绑定地址、代理认证或控制接口/认证，防止自己切断恢复通道。同一时间只允许一次试运行；残留锁需要先检查状态，不能忽略后并发启动。`.local/config-guard/trial-*/` 保留私有快照、改动字段路径、探测阶段和恢复结果，不记录凭据值。通过当前 mixed 端口获得 HTTPS 响应不等于 Codex 登录/WebSocket 正常，所以即使探测全过，**没有手动确认仍回退**。`confirmed` 只表示保留本次运行状态，不自动把它写成客户端持久化配置。

## 额度：查账户，不伪造订阅头

```bash
pnpm rola usage --proxy http://127.0.0.1:实际混合端口
```

这是单次、只读的账户查询：固定访问 `https://api2.rola-ip.co/api/users/traffic/packages/current`，使用 `Api-Token` 请求头，10 秒超时，不跟随重定向，不重试拒绝，不调用购买、续费或刷新 IP。API Token 只来自本地文件，不写进候选 YAML、订阅 URL 或输出。

必须指定当前代理软件的本机 HTTP/mixed 端口；只影响本次命令，不修改系统代理或全局环境变量。该客户端不可用就查询失败，不自动直连 Rola API。也不会为了查询用量而自动选择 Rola 作为管理请求出口。

返回的 `total_traffic` / `cost_traffic` 单位为 byte，分别显示套餐、已用、剩余；缺失字段为未知而不是 0，空套餐明确为空。文档的 `expire_time` 示例没有可靠时区，因此保留供应商原文，不伪造 Unix 到期时间或“长期有效”。实际账户响应需在获得套餐和密钥后核对。

机场与 Rola 是串联资源，同一流量经过两者，**不能把两份额度相加作为一个 `Subscription-Userinfo`**。机场原用量继续来自自己的订阅头，Rola 用量来自这次 API 查询；此工具不改变原订阅卡片。多个独立机场订阅的合并额度是另一个场景。

## 购买后验收顺序

1. 保留当前可用配置，确认实际套餐、网关协议/端口和国家；先核对一个目标网站，不同时修改 DNS/TUN/嗅探/PAC。
2. 用独立目录运行 Mihomo `-t -f 候选文件 -d 检查目录` 做语法检查；`-t` 不启动流量代理，但远程规则资源有可能需要下载。配置通过不等于节点可连接。
3. 手动导入候选配置，不立即覆盖旧配置。核对运行配置中的第一跳、Rola、域名规则和 DNS 是否被客户端覆写改变。
4. 少量请求验证出口 IP/ASN/地区、HTTPS 连通性以及会话重连后的出口变化；每个请求都可能消耗 Rola 流量。BrowserLeaks 的测试域名未必属于保护列表，要核对实际请求路由；检测一次不能证明其他应用没有绕行。
5. 再做冷启动、断网恢复、Rola 不可用时拒绝访问、客户端退出时是否漏直连、Wi-Fi/移动网络切换检查。未完成这些步骤前不将其作为账户常驻出口。

若启用 Rola IP 白名单，代理链访问 Rola 时它看到的是**机场出口**，不是 CF，也不一定是你家宽地址。第一跳换出口可能使白名单失效；不要为此自动扩大白名单或关闭认证。
