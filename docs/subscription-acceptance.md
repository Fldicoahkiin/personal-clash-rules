# 订阅转换对照与验收记录

日期：2026-10-12。这里区分代码检查、隔离测试、线上响应和实际客户端联网；一层通过不代表其他层已经通过。真实订阅地址、节点凭据和生成的私有链接不写入本文或 Git。

## 与其他转换器对照

| 项目与源码版本 | 实际实现 | 本站采用或保留的区别 |
| --- | --- | --- |
| [Sub-Store download.js](https://github.com/sub-store-org/Sub-Store/blob/a3e61061e50b40e5c5938969aab915d05d8d7069/backend/src/utils/download.js) | UA / 自定义请求头、可选本地代理、正文与用量缓存，解析后检查节点 | 本机读取可显式使用已有 mixed 端口；成功解析才缓存，按 URL + UA 隔离；不自动切换用户出口 |
| [Sub-Store flow.js](https://github.com/sub-store-org/Sub-Store/blob/a3e61061e50b40e5c5938969aab915d05d8d7069/backend/src/utils/flow.js) | 流量缓存；HEAD 没拿到需要的信息时再 GET | 补上 HEAD 无用量 / 不支持 HEAD 时的 GET 响应头读取；403、429、交互验证不当作普通方法不兼容重试 |
| [subconverter webget.cpp](https://github.com/tindy2013/subconverter/blob/a0d4eab28cb8b6c782d4ce5c3a918de4829b4a72/src/handler/webget.cpp) | libcurl 超时、重定向、代理、正文与响应头缓存，可回用缓存 | 本站用同一转换逻辑适配本地 Node 与 CF fetch；正文和头一起保存。没有照搬关闭 TLS 校验的行为 |
| [sub-store-cloudflare subscription.ts](https://github.com/realchendahuang/sub-store-cloudflare/blob/6c4f4616308826a4bf4b72d091dfc0c5cc6408f0/cloudflare/src/lib/subscription.ts) | Worker fetch、UA、五分钟缓存、条件请求与旧内容恢复 | 同类 Worker 并不自带浏览器验证通行能力。本站增加明确的本地读取 → 自有 CF 分发，不伪装成 CF 已直接读取成功 |

这不是依靠一个不同的解析库就能覆盖所有网络路径。机场同一接口从客户端、本机代理和 Worker 发起请求，可能获得不同响应。若返回有效内容，解析、名称/用量保留、重试策略、缓存和客户端格式是转换器的责任；若收到验证页，不能把它当作节点配置，更不能返回“成功”的空外壳。

本地网页的 `localhost:25500` 指的是本地 HTTP 服务，不是纯前端绕过跨域。本站 `/sub` 兼容一部分 Subconverter 参数；不支持的指令明确拒绝，不宣称任意第三方 INI、脚本、协议都等价。

## 本次修正

- 元数据：HEAD 成功但没给流量不再立即判定不存在；合理补读 GET，并取消未使用正文。
- 缓存：五分钟成功源缓存，同时保留正文、名称和用量；空节点、解析失败、验证页不能写入。原有整份最近有效配置恢复仍保留。
- 本地同步：网页生成后可同步到自己的 CF，保留固定云端链接。独立管理密钥校验更新，旧时间戳、错误密钥、空来源和来源数量不匹配不覆盖旧数据。
- 自动更新：本地服务运行时按间隔同步，失败十五分钟后重试。网页列出任务，可暂停、恢复；不安装开机启动，不操作代理客户端。
- 云端状态：保存同步时间；超过间隔返回旧内容并标记 `sync-overdue`。旧用量不会标成实时查询。
- Rola 基础来源：一个本站同步链接可以直接作为云端串联的机场基础，在内部读取记录，不让 Worker 再通过公网请求自己。后续同步的机场凭据与用量继续生效；选定前置节点被撤回时拒绝更新，不偷偷换出口。

| 用户目标 | 当前状态与证据 | 尚未完成或需要注意 |
| --- | --- | --- |
| 真正的 CF 后端，不只是前端 | Worker + KV + GitHub 生产分支自动发布；有集成测试 | 源接口从 CF 直读是否可用须按实际路径验收，不能仅看健康接口 |
| 本地后端与云端同一规则 | 导入同一解析/渲染代码、共用公开规则；本次加本地向云端同步 | 本地代码更新仍需 Git 更新、构建、重启；不是后台自动升级 |
| 多订阅与独立 IP 合并 | HTTP / HTTPS / SOCKS5 字段输入、四段格式拆分、URI 备注、多源合并测试 | HTTP/SOCKS5 不是 SSH；不可能将不支持的服务端协议靠改文件变成 VLESS |
| 订阅名与手动覆盖 | 默认值实际填入输入框；清空后可继承上游名称；多机场可添加来源前缀 | 上游没有名称时不能猜机场名；手动填写优先 |
| 流量、剩余、到期 | 读取 `Subscription-Userinfo`，单机场透传、多机场已知值合计；有响应头测试 | 缺失到期保持未知；相同账户不同 URL 不能自动判断重复；Rola 串联额度不与机场相加 |
| Clash 卡片不再只显示“远程” | 输出真实用量响应头后满足客户端显示用量的条件 | 当前客户端仍保留旧记录，未执行替换；不声称卡片已经变化 |
| 刷新不能导致节点全没了 | 空源拒绝、完整输出最近有效结果最长 24 小时恢复；同步模式保留上次快照 | 不是永久增量集合，成功更新仍移除机场撤回的节点；客户端自身错误处理不能由服务器保证 |
| 节点计数、兼容性、源模式 | 读取/输出/跳过不兼容/去重/筛除分开；Worker、本地、客户端直读、本地同步区分 | 客户端直读的节点数和排序不可用，不把 COMPATIBLE 当成可用节点 |
| 完整配置和仅节点、可折叠 | 格式注册表分组、折叠选择、图标、一键导入；页面与导入协议测试 | 未逐个在所有第三方客户端真机导入 |
| Party / Verge / FlClash | 分别输出 Mihomo 完整配置与对应导入地址，Party 使用 `mihomo://` | 不操作当前客户端；Android / Windows 真机待验收 |
| iOS Shadowrocket | 独立 `.conf` + 配套节点资源，节点用量头保留，渲染与链接测试 | iPhone 未实测；Rola 的“代理通过”链路尚未自动输出/真机验收 |
| UA 预设与自定义、进阶说明 | 页面提供预设和自定义，国家旗帜命名明确；跳过不兼容的语义分开 | UA 不是网络可达保证；跳过证书校验默认关闭 |
| 更新间隔 | 完整配置与订阅响应头按设置输出；本地同步按相同间隔调度 | 客户端可能有自己的覆盖设置；睡眠期间不会按时同步 |
| 多规则与自定义、规则测试 | Flacier、三个 ACL4SSR 方案、自定义受支持 INI；测试与转换共用编译器 | 模拟器遇到缺失 IP/进程、无法计算的规则会显示未知，不证明运行中的实际出口 |
| 减少直连、未知默认代理 | Flacier 默认代理、保留局域网；空组拒绝；默认不添加通用国内直连兜底 | ACL4SSR / 自定义方案有自己的直连规则，不能当作同一种隐私策略 |
| Claude 规则 | 域名、内容域、精确第三方地址、官方 API IP；不是复制 `FINAL,DIRECT` | 没有证据时不扩大共享监控域/ASN；登录服务可用性仍需实际出口验证 |
| DNS 模板与自定义 | 独立引导 DNS 和业务代理 DoH；IPv6 在生成配置中默认关闭；保留上游 DNS 有依赖校验 | 不开启客户端 DNS 覆写；没有宣称设备 DNS 已不出现中国；引导、浏览器和出口服务端解析仍需测 |
| 国家组旗帜、其他组图标 | 已有节点名称旗帜、策略组图标与生成测试 | 国家分组名称仍是 `US` / `JP` 等代码，尚未加用户要求的名称旗帜；节点旗帜不能算作此项完成 |
| BrowserLeaks 等入口 | DNS / WebRTC / IPv6 / DoH 检测链接已提供 | 链接存在不等于通过检测；最近设备测试仍有中国解析器，不能标记完成 |
| Rola 网页选择前置、备注、规则 | 云端与本地入口、原样账号、具体前置节点、专用域名、私密覆写 | 真实网关先前在 SOCKS5 协商时断开，尚未证明实际住宅出口可用；不能靠 YAML 合法掩盖 |
| 云端凭据管理 | 用户明确允许上传自己的 CF；链接不透明、日志脱敏；Rola 有独立撤销码 | CF 明文存储内容仍属于凭据；普通同步链接尚无撤销页面；暂停同步不等于删除 |
| 构建、部署版本时间、commit | 页脚与版本 API 分开显示，失败可重试；有测试 | Worker 版本创建时间不是流量切换完成的精确时间 |
| 出问题自动回退、定位选项 | 独立限时 guard 已有隔离测试；未确认/失败回退，默认一次一个字段 | 不自动包办所有 GUI 操作，不证明 Codex 登录/WebSocket 正常；当前没有启动试切换 |
| 所有 Party 设置逐页检查 | 先前已有本地截图与检查报告 | 本次未改 DNS、嗅探、TUN、系统代理、PAC 或当前订阅；多个开关同时变化无法证明单一原因 |
| GitHub 成都登录、安全记录 | 不能从现在请求走代理推出过去登录的出口 | 指定安全记录仍未核实，不能给原因定论；本次代码发布另行验证 CLI 写入账户 |
| CF 体验达到传统后端 | 常用多源、格式、用量、缓存、短链、规则与本地读取同步有实现 | 不等价于任意 VPS 二进制、任意脚本或任意 TCP/UDP 转发服务；转换后端不承担用户流量转发 |

## 验证范围

自动测试以该提交的 CI 为准。本轮包括真实 Worker 测试、Node 本地服务、页面浏览器操作与移动宽度检查。浏览器同步按钮/任务状态使用虚构数据验收；实际私有源的线上响应另存于本机，不把 mock 当作实网结果。Worker 测试退出码为零时仍出现已有的 workerd 关闭管道诊断，保留记录，不把它隐藏成没有输出。

本轮 2026-10-12 16:05（UTC+8）只读实测：用户机场从本机经已有代理返回 200，有 70 个原始节点、名称和用量；响应类型是 `text/html`，内容实际是有效 YAML。这证明该读取路径当时可用，不证明任何出口和时段都可用。没有修改或导入当前 Clash 配置。
